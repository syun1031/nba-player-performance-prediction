# 每日更新2026–27資料與本季回測

## 使用者需求

- 使用GitHub Actions，每天台灣時間17:00執行一次2026–27例行賽資料更新。
- 歷史回測頁新增2026–27本季已完賽的回測結果。
- 同步更新未來預測頁的本季歷史資料，發布到既有GitHub及Streamlit。

## 做法與取捨

採用「GitHub Actions擷取、驗證、回算、提交資料，Streamlit讀取結果」：沿用目前CSV資料包與固定模型，不需要新增資料庫或帳號。工作流程使用GitHub內建權杖，只在更新工作中要求contents:write，不另存個人權杖。

另一做法是讓Streamlit即時抓取並回算，但速度與官方連線狀況會直接影響使用者，因此不採用。只更新CSV不足以新增回測球季，也不符合這次已確認的需求。

## 每日流程

1. 排程設定UTC09:00，即台灣17:00；另保留Actions手動執行入口。GitHub可能延遲啟動，不能保證17:00已發布完成。
2. 以當次執行的美東日期為查詢截止，沿用NBA官方賽程、box score、完賽核對規則，僅收錄2026–27例行賽。
3. 建立新的本季歷史資料包，保留來源網址、實際取得時間、狀態核對證據與檔案雜湊。
4. 用固定兩模型對本季已完賽的合格球員場次回算；產生預測、實際得分、原始上場分鐘、誤差、特徵及排除原因。
5. 通過資料完整性、模型雜湊、時間隔離與介面相關測試後，才將兩份新資料包在同一個commit提交至main，供Streamlit部署。
6. 擷取／驗證／推論失敗則工作失敗，保留上一版線上資料，提供Actions紀錄與診斷artifact。禁止只提交其中一包。

完整快照與診斷放Actions artifact；供線上使用的小型資料包才提交Git。相同工作流程不重疊執行，推送遇到其他人的新提交時不能強制覆寫；應安全重試或失敗待重跑。

## 本季回測規則

- 沿用訓練截至2026-01-31的固定兩模型，不每日重訓、不依本季結果調整門檻。
- 近5場均分<25：直接25項＋上季＋2倍；>=25：五場均值增減25項＋上季＋2倍。
- 每筆特徵只看目標NBA日期之前的同季資料；同日及後續場次一律不讀入歷史窗口。
- 個人、所屬球隊、對手各至少5場；零分鐘不納入模型，模型分鐘沿用既有四捨五入規格。
- 使用官方球員ID對應個人歷史與上季表現；保留轉隊情形，不以同名借用資料。
- 本場是否先發取自完賽資料的實際先發；其他特徵僅使用此前日期的資料。上季表現來自2025–26。
- 賽後回算不能套用賽前Confirmed或T-30的通關流程，也不能偽造賽前取得時間；另走明確標示historical_postgame的歷史流程。
- 目標之前仍有未釐清的比賽，該日期的樣本暫不回算並列出原因；較晚或尚未開始的賽程不冒充完賽。
- 保留原始分鐘作畫面展示，模型特徵使用既有整數分鐘政策。

## 介面

- 歷史回測球季選單新增2026–27，可選擇本季已完賽的合格場次，從開季至最新資料，不等到3月。
- 2024–25與2025–26仍固定3月至季末，既有凍結結果不改動。
- 本季顯示更新時間、最近完賽日期、合格及排除筆數；無合格資料時顯示說明，不產生空選單錯誤。
- 保留球員／比賽選擇、實際上場時間在實際得分左側、前10場、逐場曲線、誤差與CSV下載。
- 明確標示「日期隔離的假設性回測」，與真正於開賽前留存的預測分開；本次不新增模型比較頁的本季四模型研究。
- 未來預測頁讀取同次更新的歷史包，保留正式先發、T-30及五場門檻。

## 驗收

- 測試後續日期與目標得分改變不影響特徵／預測，五場邊界、球員ID與分流一致。
- 檢查兩包來源一致、模型SHA不變，舊兩季凍結資料與既有驗證不受影響。
- 檢查無資料／不合格的介面，以及三季切換、圖表、分鐘位置、下載內容。
- 在GitHub runner實際手動跑一次，確認官方來源在雲端可存取，成功提交資料並在線上驗收新增球季。
- 若GitHub runner遭官方來源拒絕，明確回報，不能以本機成功冒稱Actions已可自動更新。

## 本次範圍之外

不建立每日賽前預測、不自動取得每場T-30先發、不新增盤口或投注功能。已設定的76人對活塞單次預測排程維持原設定。
