## 推薦資料契約

- 僅用目前 2025–26 例行賽快照，第一週不擴充球季。
- 專案 `player_id = PLAYER`，保留完整姓名；`team_id = TEAM`，保留球隊縮寫。這是專案識別值，不是 NBA 官方數字 ID。
- `game_id = MATCHUP + "|" + GAMEDATE`，日期固定 YYYY-MM-DD；樣本鍵為 `(player_id, game_id)`。MATCHUP 保留官方方向與文字。相同 game_id 可有多位球員；主客隊視角的同一場比賽有不同 game_id，不用此鍵直接計算聯盟場次。
- 現有快照姓名無碰撞；新增資料需核對同名、改名與跨来源姓名，歧義中止接合，不任意合併。按 player_id 與球季建立歷史，轉隊不重置。GAME_ID 官方值不再是建模必需欄位；原始資料不變，仍可供核對。
- 原 CSV 及原始 JSON 不變；衍生檔放在 `outputs/week1/model_data/`。
- MIN=0 的 83 筆球員比賽紀錄從建模目標及歷史窗口全部排除，先過濾再計算特徵；不是 83 場不同比賽。此為使用者選定的納入規則，不表示已證明這些列是 DNP。
- 已核對過濾後 26,568 筆來源紀錄（26,651−83）。特徵流程已重算歷史與切分，23,722 筆有至少五場歷史；2,846 筆歷史不足，不沿用 A 的過濾前筆數。
- MIN>0 且 PTS=0 保留，不补造未出賽紀錄。FG% 的 `-` 解析為未定義值，不補 0；第一版不把 FG% 放入模型。

## 時間政策與回測限制

個人表現與平常先發的歷史統計只使用 `history_game_date < target_game_date`。同日數據一律排除，歷史按來源日期排序；同球員同日重複視為契約違反，不以 game_id 猜測先後。

預測時，只使用目標比賽前一天或更早的比賽資料，避免用到當天或未來的結果。由於資料是在球季結束後取得，可能包含事後修正，因此回測無法完全還原當時的資訊。

未來預測功能也採用相同的歷史資料規則。新增的本場陣容資訊，僅可使用預測前已公布的確認先發與明確缺席狀態，不使用本場比賽結果。依最新決定，在預定開賽前 30 分鐘檢查先發，實際取得完整名單後、預定開賽前產生預測；若名單尚未取得則等待，不預設已公開。

## 特徵與資格

同 player_id、同球季延續過去出賽歷史，不因轉隊重置；跨球季重置。窗口以來源出賽列數計，不是球隊場次或日曆天數。

| 欄位 | 定義 |
| --- | --- |
| pts_mean_5 | 最近五筆先前 PTS 平均，也為基準預測 |
| pts_mean_10 | 最近最多十筆先前 PTS 平均，5–9 筆以實際筆數作分母 |
| min_mean_5 | 最近五筆先前 MIN 平均，保留來源整分鐘精度 |
| reb_mean_5 | 最近五筆先前 REB 平均 |
| ast_mean_5 | 最近五筆先前 AST 平均 |
| is_home | 歷史從 MATCHUP 的 VS.／@ 解析；未來由已驗證賽程與名單提供 |
| is_neutral_site | 全季官方核對完成：5 場中立為 1、1225 場非中立為 0，無空值 |
| rest_days | 目標來源日期減最後可用個人出賽日期，再減一；不是球隊休息日 |

使用者已確認：至少五筆合格歷史才預測；0–4 筆回傳 `insufficient_history`。最近窗口必要值缺失或非法時不插補、不跳過壞列改取更早資料，回傳明確原因。長間隔不任意截尾。

輸出保留 history_count、十場實際筆數、最後歷史日期、窗口 game_id、資格與原因。個人 ID、姓名、球隊及稽核欄位不直接當成原七項數值特徵；新增陣容的隊友身分屬類別特徵，表示方式於實作計畫定義。

歷史 is_home 已用官方場地與指定主隊核對，但這些仍是賽後取得的資料，不代表取得歷史截止前隊籍或賽程版本。未來缺賽程／名單時不得使用最後一次歷史球隊作可靠現役隊籍替代。

2026-10-21 使用者同意新增中立場後，is_home 在已核對中立場固定為 0，表示沒有一般主場優勢；官方指定主隊另存稽核欄位，不混用。五場兩隊皆套用，保留原 MATCHUP 與 game_id；全季其餘場次現已依官方非中立場與指定主隊核對。完整證據另見 outputs/week1/venue_audit/；原五場官方證據見 nba_venue_verification.md 及 verified_neutral_venues.json。

## 陣容特徵（2026-10-21 使用者確認）

目的是學習自己是否先發、與哪些先發隊友同場，以及平常先發隊友缺席與個人得分的關聯，不將模型關聯解讀為因果效果。

- 本場使用賽前已公布的確認先發五人，不使用預估先發。
- 依最新決定，以本場賽前正式公布的先發五人為準，不再按過去先發次數推選，也不按分鐘數排序。
- 球隊與球員各自都要有至少五場先前紀錄；球隊不足五場視為資料不足，不預測。球隊場數從完整賽程／球隊比賽資料計算，不能從排除零分鐘的個人資料推算。
- 本場先發排除自己後即為先發隊友；若要判斷「少了哪位原本先發」，比較用的參考名單尚待另定，不自行沿用取消的排名方式。
- 平常先發隊友缺席需要預測前明確不可出賽的證據；沒列本場先發不代表缺席，改打替補也不算缺席。未知／待定狀態不可當成確定缺席或確定可出賽。
- 轉隊後按本場球隊檢查五場門檻，個人表現歷史依既定規則跨隊延續；跨季重置。離隊者不能當成當場缺席隊友。

| 特徵內容 | 定義與邊界 |
| --- | --- |
| is_starter | 自己在本場確認先發五人中為 1，否則為 0；完整名單未確認則未知 |
| confirmed_starting_teammates | 本場確認先發五人排除自己；自己先發時有四人，自己替補時有五人；用集合而非任意位置順序 |
| regular_starter_teammates_absent | 暫緩實作：先另定參考名單，再以預測時已知狀態判斷少了誰，不用已取消的排名方式 |
| regular_starter_teammates_absent_count | 參考名單尚待確定；不能只用本場五人算出未列名者，也不把未知狀態當零缺席 |

陣容資料需包含球隊、球員、比賽對應鍵、確認先發、缺席狀態、資訊公布／觀察時間與來源版本；不能只從未出現在賽後 box score 推定賽前已知缺席。既有九欄 CSV 缺少這些資訊；使用者已提供歷史陣容 CSV，來源與接合限制見下節。賽前狀態與公布時間仍未取得。

歷史沒有當時先發公布／缺席時間證據時，不可直接把賽後名單當作已確認的賽前資料。可另標為假設性研究，但不能與有時間證據的結果混稱嚴格賽前回測。日級限制仍適用歷史統計；當日賽前陣容是明確新增的輸入例外。

陣容缺失、球隊未滿五場或隊籍不明時需記錄原因，不把缺失補成否。原七項特徵與五場均值基準可繼續獨立建置；陣容擴充比較必須在相同陣容完整樣本上重評原模型與基準，並報覆蓋率。隊友身分類別只在訓練集擬合編碼、處理未知類別，不能按測試表現挑隊友。

### 歷史陣容資料來源（使用者指定）

使用 `outputs/nba_2025_26/nba_2025_26_regular_season_game_rosters.csv`。非空 PLAYER_1～PLAYER_15 均代表有上場，姓名前 `*` 為先發；移除星號後進行姓名對照。每列有五名先發的基本結構已核對。

本檔是實際上場名單，足以作歷史先發／上場觀察；不含賽前時間與缺席公告，未來模式仍需另補賽前確認資訊。平常先發未列於本場名單，可標為「本場未上場」，不能直接標為「賽前確認缺席」、傷病或不可出賽；轉隊與來源缺漏需另核對。

名單的 MATCHUP 是兩隊共用客隊 @ 主隊，與得分檔各隊視角不同。接合先核對日期、TEAM、對手及姓名對照，再沿用得分檔的專案 game_id，不修改使用者已確認的鍵。五筆主客方向差異不可靜默覆寫；姓名差異需明確對照。詳見 [陣容來源核對](roster_source_audit.md)。

輸出另存 outputs/week1/teammate_encoding/。每位訓練樣本中出現的先發隊友各一欄，當場在名單中為 1，否則為 0（multi-hot）；名單順序不影響結果，不把球員編號當成有大小關係的數字。356 位隊友類別只從 13,281 筆合格訓練樣本建立，不使用得分標籤或驗證／測試姓名。

訓練／驗證／測試樣本仍為 13,281／3,462／6,979；含未知隊友的比例為 0%／14.6%／29.2%。這是覆蓋率核對，不是測試誤差；不因測試出現未知姓名就擴充訓練類別。未知人數在訓練時皆為零，不能宣稱學會未知球員影響。全套 44 項測試及實際資料逐列核對通過；Scikit-learn 訓練串接與模型效益比較尚待執行，歷史賽後名單的限制仍適用。
