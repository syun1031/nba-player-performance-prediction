## 1. 目的、範圍與依據

本規格供 NBA 球員單場得分預測專案後續實作與評閱使用：比較最近五場平均得分、線性迴歸、決策樹與 XGBoost，確保時間因果順序與比較公平性。每筆樣本為一位球員的一場比賽，預測以會出賽為前提；保留實際出賽且得零分的紀錄，未出賽不補零。

依據根目錄 `PRD.md`、`TODO.md`、`PROGRESS.md` 與既有 `outputs/nba_2025_26/nba_2025_26_regular_season_player_game_logs.csv`。本次只唯讀檢視既有 CSV 的日期與筆數，未重跑完整資料核對、未採用其他 session 新產出、未訓練模型或實作正式基準。文件內的「應」表示建議的評估契約；所有待確認項目須另行定稿。

### 不可違反的切分條件

- 以統一的 GAMEDATE 定義分組，同一天所有球員及所有比賽必須落在同一集合；禁止隨機切分、隨機 K-fold 或按球員各自切分造成日期交錯。
- 滿足 `max(train_date) < min(validation_date) < min(test_date)`，且驗證的最大日期早於測試最小日期；三集合樣本鍵互斥。
- 日期缺漏不補造樣本；排序須以解析後日期進行。日期時區、官方比賽日與同日多場紀錄規則須定稿。
- 不為滿足每個球員的樣本比例把紀錄搬到其他集合；晚加入球員仍保留原日期，依共同冷啟動規則處理。

### 單球季限制

只能評估同球季較晚日期的泛化，不能据此宣稱能泛化到下一球季、季後賽或不同名單／規則環境。球季開頭沒有上一球季暖身歷史，會影響近期統計及新球員覆蓋。交易、傷後復出、賽季末輪休與角色改變可能讓時間區間難度不同；同一球員與同一場比賽的樣本相關，26,651 列不代表相同數量的獨立觀測。少數月份的調參結果有不確定性，應保留日期／球員覆蓋與分時段誤差，未來取得多球季資料後另設跨球季測試。

## 3. 訓練資料與預測歷史的邊界

模型訓練集合決定哪些列的目標值可用來估計模型參數；預測歷史集合決定在某個預測截止時間之前，哪些已完成且已可取得的比賽可用來計算特徵。兩者不必相同。

定義樣本 i 的截止時間為 c_i，可用歷史為 H_i：同一球員此前實際出賽、比賽已完成且結果已於 c_i 前可取得的紀錄。禁止當場與未來資料。過去實際 MIN、PTS、REB、AST 等可進入歷史摘要，本場實際數據不可作特徵。主客場、休息天數等也須在 c_i 前已知。

現有 CSV 只有日期、沒有結束或發布時間。**推薦暫定日級保守協定**：日期 d 的所有預測，只可用 `GAMEDATE < d` 的合格歷史；同日資料即使檔案排序在前也不能使用。這可避免以列順序冒充比賽完成時間，但不代表已證實隔日結果一定可取得。若要改為同日逐場更新，必須先有可靠完成時間、來源發布時間、預測截止時間及時區，並明訂 `available_at < c_i`；資料不足時不能宣稱完成該種回測。

### 固定模型、依時間更新歷史的測試流程（設計）

1. 在測試開始前，鎖定特徵、資料規則、前處理、模型參數及預測輸出規則。模型權重在整個測試期間固定。
2. 以測試之前已完成且可用的比賽初始化歷史狀態；可包含訓練期與驗證期紀錄，無論該紀錄當時是否因暖身不足而未用於模型訓練。
3. 日期 d 開始時凍結歷史快照，對当天全部合格樣本產生预测；保留樣本鍵、截止時間、歷史最大日期與預測值。
4. 當天比賽完成、結果可取得後才記錄真值。依日級協定，最早於後續日期把合格紀錄加入歷史；先前測試比賽的 PTS 等可供後續測試比賽的近期特徵使用。
5. 更新歷史不更新模型、補值統計、編碼字典、標準化參數、超參數或已產生的預測。不得把整個測試期球員平均等未來摘要提前算入。

例如三月十日的預測可使用三月八日已完成的測試比賽，但不可使用三月十日或十一日結果；三月八日結果不會因此變成可重新訓練模型的資料。此協定模擬持續手動更新資料、固定模型的使用方式；若改成定期重訓，須另立實驗與報告，不能混入本次比較。

回測使用已觀察到出賽的名單，故指標是「實際出賽者條件下」的得分誤差，不衡量是否出賽預測；未來使用流程須另定賽前候選名單來源。

## 4. 最近五場平均得分基準與冷啟動候選

对樣本 i，依穩定球員識別碼取得 H_i 中最近五場實際出賽，按有效比賽順序排列。若有至少五場，基準為 `prediction_i = (PTS_1 + ... + PTS_5) / 5`。窗口是出賽場數，不是五個日曆日或球隊五場比賽；出賽零分納入，未出賽不占窗口，不使用本場得分。推薦同球員跨交易保留歷史，是否改用球隊內歷史仍需特徵規格確認；不以姓名作唯一鍵。

历史不足候選處理（均未決定）：

| 候選 | 1～4 場 | 0 場 | 影響 |
| --- | --- | --- | --- |
| 嚴格五場，推薦主比較起點 | 不提供基準、排除主比較 | 同左 | 定義最清楚，但降低新人與早期樣本覆蓋；不得只排除基準而保留其他模型來比較 |
| 可用場數平均 | 用現有 n 場平均 | 不預測或採預先鎖定 fallback | 提升覆蓋但波動較大，應命名為「最多五場平均」並按歷史數分層 |
| 收縮／階層 fallback | 球員平均與固定先驗加權 | 使用先驗 | 需定義權重與先驗；先驗只能由當次擬合訓練資料估計，不能取全球季平均 |
| 額外球季作暖身 | 用真實可取得的前球季歷史補足 | 仍按無歷史規則 | 現有資料無法採用；新增資料後需重作切分、版本與評估設計 |

fallback 可考慮訓練期聯盟出賽平均或經確認分組先驗，但不能虛構球員資料、把未出賽補零，或用驗證／測試真值估計先驗。權重、分組與先驗若要調整，只能在開發期決定。最終規則須同时用於訓練特徵、歷史回測與未來預測。

## 5. 四種方法的共同評估樣本

先按模型無關規則建立樣本母集合 U：在該時間集合內、有實際出賽、合法目標得分、可解析日期與可追溯且唯一的球員／比賽鍵。目標缺失不能補值；出賽判定不可直接以四捨五入後 MIN > 0 代替，需等資料規則確認。

再建立統一 eligibility 規則 E，例如嚴格五場基準需要至少五場；若共同特徵中有不可補值的十場摘要，主比較可能需要十場。這是待確認的涵蓋限制，不能默認只需要五場。各方法共用 `C = {i in U : E(i)}`，並將鍵清單、日期、合格狀態與排除原因鎖成評估 manifest。驗證與測試各有自己的 C；同一集合內四種方法的真值、排序與權重必須完全一致。

- 可補值的特徵缺失由训练期擬合的共同規則處理，不得讓線性迴歸自行 dropna、XGBoost 保留缺失，最後用不同 N 比較。
- 模型可用不同的合法前處理，但共同輸入資訊與樣本資格不能因模型結果而變動；類別未知值處理需預先定義。
- C 中任一方法未產生有限預測值，視為評估失敗，記錄原因並修正流程；不能事後只刪除該模型失敗紀錄。若確需變更資格規則，重新版本化 C 並對四種方法全部重算。
- 不推薦事後取各模型成功預測交集：它可能掩蓋失敗與選擇偏差。若提供探索性交集結果，須另列且不能替代主比較。
- 主表使用共同 N；另報 U、C、覆蓋率 `|C|/|U|`、排除原因及各模型預測成功率。原因可能重疊，需同時提供固定優先順序的互斥原因彙總，以核對總數。
- 冷啟動／不同 fallback 的次分析也必須為每個子群建立四方法一致集合；不得用主表與不同覆蓋率的次表直接宣稱某模型較好。

## 6. 指標、報表與必要圖表

令共同集合中真值为 y_i、預測为 p_i，殘差定義 `e_i = p_i - y_i`（正值表示高估）。主要指標 `MAE = sum(abs(e_i))/N`；輔助指標 `RMSE = sqrt(sum(e_i^2)/N)`，單位皆為得分。主要採每筆球員出賽等權重，故出賽較多球員權重較高；球員等權平均可作補充，須另行標示。N=0 時標示無法評估，不填零；使用未四捨五入預測計算指標。

共同表至少包含：集合與日期範圍、資料／規格版本、方法、MAE、RMSE、N、不同球員數、有樣本日期數、母集合 N、覆蓋率。另列相對基準的 MAE 差值 `MAE_model - MAE_baseline`（負值较好）；驗證與最終測試分表，不把兩者混合。原始列數、品質合格數、共同評估數應分列。

必要圖表均使用相同 C、相同座標／分箱與明確 N：

1. **預測對實際得分散點圖**：四方法分面，含 y=x 參考線，觀察系統性低估高得分。
2. **殘差診斷**：殘差對實際得分散點圖，含零線；另以相同 bins 呈現殘差直方圖，觀察偏差、長尾與離群值。
3. **實際得分區間誤差**：候選區間 0～9、10～19、20～29、30 分以上；每區間列 MAE、RMSE、N。分箱在測試前鎖定，真值分箱僅用於事後診斷，不用來決定預測資格或特徵。
4. **按時間的誤差**：以週或月列 MAE 與 N，觀察球季後段漂移；低 N 不合併掩蓋，無樣本區間標空。

按球員與歷史場數的誤差表為補充；個案選取需說明規則，不能只展示成功案例。若報不確定區間，推薦按完整比賽日作成對區塊 bootstrap，四方法共用重抽樣日期，以保留部分日內相關性；此為評估後的不確定性估計，非隨機資料切分，也不能消除單球季與跨日相關的限制。不在本次草案承諾顯著提升幅度。

## 7. 前處理、調參、選模與最終測試

| 階段 | 可以做 | 不可以做 |
| --- | --- | --- |
| 開發擬合 | 在訓練列 fit 缺失補值、編碼、標準化、資料驅動門檻與模型 | 用驗證或測試列 fit／估計統計；用全球季球員平均補值 |
| 驗證／調參 | 套用已 fit 流程，依截止時間建立歷史，有限搜尋超參數，選特徵與冷啟動候選 | 將驗證指標稱為最終測試；在同折把驗證真值加入模型訓練 |
| 規則鎖定 | 固定日期、C 的建置規則、特徵、超參數、輸出處理、選模規則與重擬合策略 | 看到測試結果後改上述規則以提升數字 |
| 最終測試 | 固定模型作時間順序預測，歷史只依完成／可取得條件更新；四方法共同評估 | 重訓、再次調參、更新擬合統計、事後挑選最佳測試模型部署 |

若採 expanding-window，每一折獨立 fit 前處理與模型，只用該折訓練日期；不能把其他折較晚日期的擬合物帶入。

**選模提案**：在共同驗證 C 以 MAE 最低優先、RMSE 次之；若要採「近似平手選較簡單模型」，須事前訂差異門檻，不能看結果後臨時宣布平手。每種模型的搜尋範圍、試驗上限、隨機種子與預算需先記錄。XGBoost early stopping 只能使用開發期驗證，決不能使用測試；最終若重擬合需固定已選的迭代輪數。基準也須納入選擇討論，不預設學習模型一定勝出。

**最終擬合的兩個候選**：

- 候選 1：保留訓練期擬合的模型与前處理，直接進入測試；訓練／驗證邊界最清楚，但少用二月訓練資訊。
- 候選 2（推薦討論）：驗證選定規格後，把原訓練＋驗證合併為「最終訓練集合」，重新 fit 前處理及三種模型，再固定到測試結束。這時二月是最終訓練資料，不能再聲稱它是該模型的獨立驗證；原驗證分數保留為開發選擇紀錄。

須在開啟測試前選一個策略，所有三種模型一致；若基準有擬合先驗，也依同一策略重估。最終測試可展示四方法比較，但部署候選應由驗證選定；测试發現問題可揭露限制，不能在同一測試集反覆修正後當作新的未見資料驗收。若改了會影響預測的規格，須標示測試已用於開發，另安排新保留資料。

目前允許唯讀查看測試日期與列數以提案切分，不等於允許依其得分分布、誤差或特徵效果做選擇。將來負分截斷、四捨五入、異常值處理等會改變指標的規則，也必須在測試前定稿。
