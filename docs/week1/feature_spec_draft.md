## 2. 樣本、目標與識別契約

| 項目 | 定義 |
| --- | --- |
| 歷史監督樣本 | 官方確認有出賽的球員 p 與已完成例行賽 g；每個 `(player_id, game_id)` 一筆。資格判斷只定義標籤／評估母體，不作為賽前輸入。 |
| 目標 y | 該場官方 PTS，非負整數，含延長賽；真實 0 保留。缺失或不合法的標籤不插補，隔離並列明排除原因。 |
| 未來請求 | 截止時間前已知的球員、目標比賽及所屬隊；不因未來是否真的上場而篩選輸入。輸出標示「以球員出賽為前提」，不估計出賽機率。 |
| 球員鍵 | 官方穩定 `player_id`，以字串保存；姓名僅供顯示與核對。不得把姓名正規化結果當永久唯一鍵。 |
| 比賽鍵 | 官方 `game_id`，以字串保存前導零；延期沿用來源的比賽身份／修訂規則，不用日期重新造鍵。 |
| 球隊鍵 | `team_id` 與每場／每個截止時間的 team 關聯；不把 team 放入球員歷史分組鍵。 |
| 預測紀錄鍵 | `(player_id, game_id, cutoff_at, feature_spec_version)`；另存模型／前處理版本與來源快照 ID，允許同一場多次賽前請求。 |
| 稽核欄位 | season、season_type、官方比賽日期、開賽時間與時區、資料可取得時間、出賽狀態、來源版本；這些不是全部都要進模型。 |

CSV 與原始列對接時，姓名、TEAM、MATCHUP、日期與數值只能作核對線索；不得依檔案列序直接接合，或對重名／多重候選任意取第一筆。未能確定 ID 的列暫不進入建模母體並報告覆蓋率；不得用姓名＋日期替代已驗證的比賽鍵。同一球員同日多場需時間與 game_id 解歧，game_id 只能穩定排序，不能代表時間先後。

## 3. 截止時間與歷史集合：不可放寬的約束

所有特徵、身份／球隊關聯、目標賽程，以及任何補值所需資訊，只可使用預測截止時間以前已可取得的資訊。`available_at < cutoff_at` 採嚴格小於；只有資料已發布／取得且比賽已完成的歷史結果才可使用。目標場的任何賽後欄位不得進入特徵。

**推薦第一版截止政策（尚待確認）**：對目標官方日期 D，使用該日期在來源指定時區的日初為 cutoff；只用官方日期小於 D 的歷史比賽。未來若用於當日稍晚請求，仍凍結於此 cutoff。同日已完賽結果一律不加入。這可配合日期切分，也避免僅有日期時猜測同日先後；需核對時區、跨午夜與 cutoff 確實早於目標開賽。日初並不保證前一天所有結果已發布，仍須通過完賽／available_at 檢查。

若改採開賽前固定時距或請求當下截止，必須另訂時距、延期與時區政策，並有版本化賽程及發布時間；歷史回測也要重建相同 cutoff，不能只改未來模式。

令 H(p,g,c) 為同一 player_id、同一球季、例行賽、有出賽、排除 g，且比賽已完成並於 c 前可取得的紀錄，依實際開賽時間由早至晚排列；第一版日期模式再加 `history_date < target_date`。若歷史同日排序無法判定，隔離歧義，不任意決定先後。推薦第一版不跨球季。

W_k 為 H 最後 k 筆，`n_k = min(k, |H|)`。所有 rolling 必須先依球員與時間排序、排除當場，再取視窗；通常相當於分組後先 shift(1) 再 rolling，但 **shift(1) 不足以保證 available_at、同日及球季約束**，仍須先按上述集合過濾。不得先算含當場的 rolling，再於輸出階段刪當場。

現有季末 CSV 無發布時間。若找不到歷史版本，僅能做「先前比賽結果於 cutoff 前已發布、且無後續修訂影響」的假設性回測，必須揭露假設，不能宣稱已驗證完整 point-in-time 一致性。若無法合理支持該假設，嚴格賽前回測須暫緩。

## 4. 精簡第一版候選特徵

推薦 7 個模型輸入：得分均值 5／10 場，分鐘、籃板、助攻各 5 場均值，加主客場及休息天數。第一版不加入波動、趨勢、對手強度、球員／球隊編碼、FG% 或本場預估分鐘；需後續驗證才可確認採用。ID 只用於接合、排序及歷史分組。

共通公式：`mean_k(X) = Σ_{h∈W_k} X_h / n_k`，只在完整視窗內該欄位全部合法且 n_k > 0 時計算。零值為合法值；不跳過壞值改取更早比賽，也不以零補資料缺口。分鐘非負且可含延長賽，不能以 48 分鐘上限裁切。

| 特徵 | 公式／單位 | 所需欄位 | 賽前可取得性 | 缺失值處理（推薦） | 資料洩漏風險與限制 |
| --- | --- | --- | --- | --- | --- |
| pts_mean_5 | mean_5(PTS)，分 | player_id、game_id、season、PTS、歷史時間及 available_at | 過往完賽結果已發布才可用 | 少於 5 場暫不預測；視窗任一 PTS 無效則隔離該請求 | 含當場 PTS、未來場、晚發布或事後修訂均洩漏；也是五場平均基準值 |
| pts_mean_10 | mean_10(PTS)，分；5–9 場以現有 n_10 為分母 | 同上 | 同上 | 已有至少 5 場時允許不足 10 場；任一 PTS 無效則隔離 | 不可為湊滿 10 場取未來結果，亦不可用全季均值補滿 |
| min_mean_5 | mean_5(MIN)，分鐘 | 共通歷史鍵／時間、MIN | 只用已發布的過往 MIN | 最近 5 場任一 MIN 缺失／不可解析，暫不預測 | 本場實際 MIN 禁用；官方顯示整分鐘可能有精度限制；如為 mm:ss 須確認後統一轉分鐘 |
| reb_mean_5 | mean_5(REB)，個 | 共通歷史鍵／時間、REB | 只用已發布的過往 REB | 最近 5 場任一值缺失／非合法非負整數，暫不預測 | 本場 REB、全季回填及後來修訂不可直接混入 |
| ast_mean_5 | mean_5(AST)，次 | 共通歷史鍵／時間、AST | 只用已發布的過往 AST | 最近 5 場任一值缺失／非合法非負整數，暫不預測 | 本場 AST、全季回填及後來修訂不可直接混入 |
| is_home | 目標球員隊為指定主隊則 1，指定客隊則 0 | cutoff 前的目標 game_id、球員所屬 team_id、home／away team_id；歷史 MATCHUP 作核對 | 由賽前已公布賽程與隊籍決定 | 賽程、隊籍或主客關係不明時暫不預測；中立場如採指定主客需來源確認 | 不可由賽後最終名單推回當時隊籍；延期／主場更動用當時版本。歷史 VS.／@ 僅為候選映射 |
| rest_days | `date(g) − date(last(H)) − 1`，完整間隔日數；相鄰日期為 0 | 目標官方日期、最後一筆可用個人出賽日期、共通歷史鍵／時間 | 目標日期已公布且上次出賽結果已可用 | 無上次歷史則暫不預測；負數／日期歧義隔離；不以 0 代替缺失 | 定義為距最後「可用個人出賽」的間隔，非球隊休息、實際恢復或傷停長度；不可向後找下一場，亦不可用賽後更新日期替換當時賽程 |

稽核輸出另保留 history_count、n_5、n_10、last_history_game_id／date、max_history_available_at、eligibility_reason、是否已知近期轉隊與距上次出賽日數。第一版不把這些全數加為特徵；對不足 10 場與長缺陣樣本另外報告覆蓋率／誤差，避免隱藏品質差異。

## 5. 邊界情境、選項與推薦

| 情境 | 選項與取捨 | 第一版推薦（未確認） |
| --- | --- | --- |
| 歷史不足 | A：滿 10 場才預測，視窗一致但覆蓋較低。B：至少 5 場，10 場窗可用 5–9 場，保留更多樣本且基準有完整 5 場。C：1 場即預測或以先驗補值，覆蓋較高但估計不穩並增加規則。 | B。1–4 場顯示資料不足；5–9 場用真實分母；10 場以上正常。全模型及基準共用此門檻。 |
| 新球員／無歷史 | A：聯盟／位置均值，需訓練期先驗及可靠位置資料。B：拒絕數值預測，限制明確但未覆蓋新人。 | B。不把「資料集沒有紀錄」等同 NBA 新秀；可能是歷史範圍不足。UI 說明所需至少 5 筆可用出賽紀錄。 |
| 轉隊 | A：以球員 ID 延續歷史，簡單、保留樣本，但角色變動可能造成誤差。B：轉隊重置，較貼近新角色但冷啟動更多。C：混合加權，增加參數與驗證成本。 | A。同球季沿用球員歷史，不按 TEAM 分組；目標主客場依 cutoff 前已知的新隊籍。角色變動為限制，可標記但不新增第一版模型輸入。 |
| 跨球季 | A：球季重置，清楚且符合目前單季範圍，但季初不可預測。B：跨季延續，增加覆蓋但需多季來源且舊角色可能失效。C：衰減／限制間隔，需額外規則。 | A。球季第一至第五筆出賽均因先前未滿 5 場而不預測，第六筆起才可能合格。前季歷史與季後賽不混入；多季擴充後可重新比較，不能自動變更。 |
| DNP、傷停、未登錄 | A：補零，混淆出賽與得分任務。B：不入出賽窗，與 PRD 一致。 | B。不創造樣本或標籤，不佔 W_k；不更新最後出賽日期。已確認出賽且 0 分保留。MIN 顯示 0 可能是四捨五入短暫上場，不能僅以 MIN > 0 判出賽，須核對來源狀態。 |
| 長期未出賽 | A：保留最近出賽窗與原始間隔，簡單但回歸狀態不可靠。B：超過某天數重置／截尾，需驗證門檻。 | A，不任意設日數門檻或截尾；顯示歷史日期與資料更新時間，揭露休息值不是健康狀態。 |
| 欄位缺失／來源漏場 | A：訓練集擬合補值，增加覆蓋但可能掩蓋缺漏。B：拒絕不完整請求，較少樣本但規則可稽核。 | B。缺漏場不能當作真實未出賽；來源完整性未知時標記不可評估／不可預測，先核對再放行。 |

第一版推薦不做數值插補，因而沒有需要從全體資料估出的補值。若後續改採補值，補值器、標準化或編碼只可在訓練集擬合並凍結於驗證／測試／未來推論；早於模型訓練截止的歷史預測，不能使用尚未存在的訓練先驗或模型。

## 6. 歷史回測與未來推論共用規則

兩種模式都以相同規格版本接受「player_id、game_id、cutoff_at、截止前賽程／隊籍、截止前可用歷史快照」，輸出相同 7 個欄位、順序、單位及資格原因。歷史模式另外接合賽後 PTS 作評估；未來模式沒有目標值，也不得用空白本場統計或假零佔歷史窗。

共同處理順序：驗證識別鍵與賽程版本 → cutoff 篩選可取得資料 → 同球員／球季／例行賽有出賽歷史 → 排除當場與同日資料 → 排序取最後 5／10 場 → 核對數值與門檻 → 計算特徵 → 使用已凍結模型及前處理。任何一步無法確定，都回傳原因而非虛構數值。

按日期切分，同一天不得跨集合。驗證與測試可用 cutoff 前已發布的較早驗證／測試比賽結果更新歷史窗；這是逐日推進的回測，不能重擬合模型、補值器或用未來標籤調參。這項推薦政策須在報告中明列，若需求改為整段預測時凍結歷史，應另版規格並同步改未來請求方式。

共同可評估集合先由身份、出賽標籤、截止前資料、完整欄位和至少 5 場歷史判定，不能因某模型誤差大小挑選。所有模型與五場均值基準在同一集合算 MAE／RMSE；模型失敗需報告，不能只為該模型刪列。另報告原始出賽樣本數、各排除原因與覆蓋率，避免排除新人後只呈現較容易的樣本。

未來球員最後未出賽時，該請求保留稽核紀錄但不給零分標籤，也不納入條件於出賽的得分誤差。過期、取消或延期賽程需作廢／重建請求；新 cutoff 使用當時可取得的新版本，不覆寫舊預測。

## 7. 後續實作的驗收案例（本次僅定義）

- 前 5 場 PTS 為 10、20、0、30、40，第 6 場為 99：第 6 場 pts_mean_5 與 pts_mean_10 均為 20；更改 99 不得改變該場特徵。
- 第 11 場僅用先前第 6–10 場算五場窗，第 1–10 場算十場窗；任意修改第 12 場以後結果不得改變第 11 場特徵。
- 出賽 5 次後插入 DNP：下一次窗仍是那 5 次；上次出賽日期不隨 DNP 更新。有出賽零分仍佔一筆。
- 同球員轉隊保持歷史；目標隊籍不明不預測。跨球季則重置；僅有 4 場歷史與視窗數值缺失各回傳明確原因。
- 日期 10/23 上次出賽、10/25 目標：rest_days = 1；10/24 目標為 0。同日結果即使已完賽，日期截止政策仍排除。
- 歷史比賽早於目標但 available_at 晚於／等於 cutoff 時不得入窗；賽後才修訂的賽程、隊籍、數據不得冒充當時版本。
- 給歷史與未來入口完全相同的請求與快照，應得到同樣特徵及資格結果；只有歷史入口可另外接標籤。
- 每列紀錄驗證最大歷史日期小於目標日期、最大 available_at 小於 cutoff、當場 game_id 不在窗、視窗 ID 無重複；模型與基準評估鍵集合相同。
